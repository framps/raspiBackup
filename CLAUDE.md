# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout

- `raspiBackup.sh` – the backup tool, one large bash script (~400 KB). Search it with grep instead of reading it whole.
- `installation/raspiBackupConfig.sh` – installer/configuration UI (published also as `raspiBackupInstallUI.sh`).
- `build/` – Debian package and signed apt repository (gh-pages). See `@build/README.md` for releases, version numbering and suites.
- `published/` – files that installations without apt download from `master`. Generated by `./publish.sh`, never edit by hand.
-  purpose of this branch is to migrate the old pubish/install way of the raspiBackup package which includes raspiBackup and raspiBackupInstallUI in the past to use apt and rename raspiBackupInstallUI to raspiBackupConfig

## Conventions

- `raspiBackup.sh` may only be changed for the apt update/package handling (version detection, update news, DEPRECATED, migration hints). Never change backup or restore logic.

- Indentation: tabs in `raspiBackup.sh` and `installation/raspiBackupConfig.sh`, 4 spaces in `build/` scripts.
- `$Sha1$` and `$Date$` are placeholders substituted by `publish.sh` / `build/build.sh`. Keep them literal.
- The `VERSION` suffix drives behavior: `beta`/`alpha` → beta, `hotfix` or `-m_` → hotfix, `dev` → dev.

## Verification

- Lint as CI does: `shellcheck -S warning --shell=bash raspiBackup.sh` (same for `installation/raspiBackupConfig.sh`).
- `build/test/testPackageUpdates.sh` is the functional test for package install/update/revert and migration. It needs sudo, installs and purges packages, and tests only committed code. Run it only on a test system (VM, spare Raspberry), so ask before running it.

## Do not run without asking

`./publish.sh`, `build/build.sh`, `build/publishRepo.sh`, `make deploy`/`update`/`buildFiles` (the latter does `git checkout -f`). They sign, publish to users/GitHub Pages/the website, or discard local changes.
